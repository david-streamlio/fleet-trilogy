What the chart alone won't tell you

Four things the numbers above hide, each one a real finding from this evaluation round — the case for "consider more than accuracy and speed."

Parsing fine isn't judging well

Llama-3.1-8B and GLM-4-9B-0414 parse at 96.7% and 100% — better than the models that passed. Both still fail on judgment: severity mismatch of 50.6% and 57.8%. Format and calibration are different capabilities; a model can ace one and fail the other.

llama-3.1-8b-instruct-q4km · glm-4-9b-0414-q4km

Hardware can disqualify a model the benchmark never touches

Qwen3.8-27B is disqualified for confirmed thermal issues on the Pi 4 — a fact no accuracy or M4 latency number captures, and true regardless of how it scores.

qwen3.8-27b-q4km · models.toml: enabled = false

The median hides the worst case

Qwen3.8-27B's own p50/p95 split makes the point on its own: 4.2s median, 25.2s 95th percentile — a single call almost 6x its typical time. A dashboard showing only p50 would call this model stable.

latency_p50 4.21s → latency_p95 25.16s

Reasoning tokens spend time before the JSON starts

Qwen3-8B is the only gate-2 PASS with real latency headroom to spare — its reasoning-model architecture emits hidden `<think>` tokens before the actual answer, a cost invisible to format/severity checks but very visible on constrained target hardware.

qwen3-8b-q4km · latency_p50 6.83s for a 4.68 GB model

Dev-machine numbers are quality signal only

The only two models with a real Pi 4 decision-grade run so far show why the M4 latency column above can't be read as a deployment estimate.

Qwen2.5-1.5B-Instruct: 0.98s median on the M4 → 111.5s on the real Pi 4. 114x slower on target hardware.

Qwen2.5-0.5B-Instruct: 1.22s median on the M4 → 70.7s on the real Pi 4. 58x slower on target hardware.

Every other row in the ledger above is "quality‑only" — a real accuracy signal, but a hardware footprint number from the wrong hardware.

Which sets up the next question Running this ledger once, on CPU, already costs real wall time: the 15-model Edge Triage Pipeline pass alone ran 54 minutes, and individual calls on the heaviest model reached 25 seconds each. That's the cost of evaluating models — not deploying them — and it's the argument for putting the harness itself on GPU-backed infrastructure, even though every model above still has to run on constrained CPU hardware once it ships.
